## Цель для обучающегося

Обучающийся должен увидеть, что STP делает в живой сети: найти корневой мост (`This bridge is the root`), найти заблокированный альтернативный порт (`Altn BLK`), а после обрыва рабочего канала наблюдать, как этот порт за время Forward Delay проходит состояния `LRN` → `FWD` и связь восстанавливается по резервному пути. Заодно — понять, что происходит без STP (дублирование кадров, нестабильность таблиц MAC, широковещательный шторм).

Текст темы (5.1.1–5.1.7) объясняет проблему петель и алгоритм STA на абстрактных схемах из восьми коммутаторов. Видео добавляет: (1) ту же идею на минимальном треугольнике из трёх коммутаторов; (2) первую встречу с выводом `show spanning-tree vlan 1` (Root ID / Bridge ID / таблица портов с ролями и состояниями) — команда в тексте темы 5.1 не вводится; (3) живую демонстрацию перерасчёта: syslog о падении Fa0/1, `Root LRN`, `Root FWD`, Aging Time 15 с.

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер), ~4:30. Часть 1 — анимация треугольника (можно вынести как отдельную анимацию Figma ≤ 60 с «сеть с STP / без STP»); часть 2 — сессия симулятора (терминал + мини-топология с подсветкой состояний портов). Сценарий одновременно становится учебным видео для симулятора по теме «STP: роли и состояния портов, перерасчёт».

Сцены для генератора:

1. **Титул** → «Наблюдение за работой STP» → «Посмотрим, что делает STP в сети с резервным каналом — и что будет без него.»
2. **Треугольник с STP** → S1/S2/S3, PC1 у S1, PC2 у S2, ⊘ на S1–S3; стрелки PC1→S1→S2→PC2 → «STP нашёл петлю и заблокировал один порт. Пинг от PC1 к PC2 идёт через S1 и S2.»
3. **Отказ S1–S2** → ✗ на канале, ⊘ исчезает, стрелки через S3 → «Канал упал — STP разблокирует порт, и трафик идёт через S3.»
4. **Без STP** → заголовок перечёркнут; стрелки по кругу, ✗ у PC2 и PC1, «?» над коммутаторами → «Без STP кадр с неизвестным назначением уходит во все порты, идёт по кругу, PC2 получает дубликаты, таблицы MAC «скачут» — широковещательный шторм.»
5. **Живая сеть** → та же схема с IP (S1 .1, S2 .2, S3 .3, PC1 .100, PC2 .101), окно терминала → «Соберём это на реальных коммутаторах. S2 — корневой мост.»
6. **ping с PC1** → терминал Windows, 4 ответа → «Связь есть.»
7. **show spanning-tree на S1** → вывод с подсветкой `Root ID`, `Port 1 (FastEthernet0/1)`, строки `Fa0/2 Altn BLK` → «S1 не корневой: корневой порт — Fa0/1 к S2, Fa0/2 — альтернативный, заблокирован.»
8. **telnet на S2** → вывод с подсветкой `This bridge is the root`, все порты `Desg FWD` → «На корневом мосту все порты назначенные и передают.»
9. **Обрыв кабеля** → на схеме ✗ на S1–S2; в терминале syslog `%LINEPROTO-5-UPDOWN … FastEthernet0/1 … down` → «Отключаем кабель S1–S2.»
10. **Learning → Forwarding** → два вывода подряд: `Fa0/2 Root LRN`, затем `Fa0/2 Root FWD`; Cost 19 → 38, Aging Time 300 → 15 → «Fa0/2 стал корневым портом: сначала learning, через 15 секунд — forwarding. Стоимость до корня выросла до 38.»
11. **ping снова** → 4 ответа; на схеме путь через S3 → «Связь восстановлена по резервному пути.»

Ассеты: треугольник из трёх коммутаторов (S1, S2, S3) с двумя ПК, значки ⊘ / ✗ / «?», стрелки потока; макет терминала (PuTTY-подобный) и Windows cmd; подсветка строк вывода.

But this causes potential loops in the environment. In this case the spanning tree protocol has recognized there's a loop in the environment and it's shut down one of the links.
[0:24] This is what we want the spanning tree protocol to do. So right now when PC1 pings PC2 it takes that pathway. Now what if the link goes down between S1 and S2? [0:46] and change it from blocking to forwarding, and now we have our alternate path to reach PC2 and redundancy has been achieved. Now what happens when we don't have spanning tree protocol? S1 will forward a packet to an unknown destination out of both ports
