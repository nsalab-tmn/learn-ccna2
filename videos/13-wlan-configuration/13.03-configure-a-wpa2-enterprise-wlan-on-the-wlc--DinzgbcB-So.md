## Цель для обучающегося

Обучающийся должен понимать, что на WLC **порты** — физические (5 штук на 3504: один SFP + четыре медных), а **интерфейсы** — виртуальные (как SVI/interface VLAN), что каждой WLAN нужен свой интерфейс, и уметь создать динамический интерфейс: имя + VLAN ID → порт 1, адрес WLC в этой VLAN `192.168.5.254/24`, шлюз `192.168.5.1` (R1), адрес DHCP-сервера `192.168.5.1` (DHCP для клиентов — на маршрутизаторе, внутренний DHCP WLC — только для AP/управления) → Apply → проверить в списке интерфейсов → привязать к WLAN вместо `management`.

Текст темы (13.3.6–13.3.7) описывает те же шесть шагов на тех же экранах (имя `vlan5`, адрес 192.168.5.254, шлюз 192.168.5.1, Primary DHCP 192.168.5.1) и добавляет вывод `show ip interface brief` на R1 (подинтерфейсы F0/1.1 192.168.200.1 и F0/1.5 192.168.5.1). Видео добавляет: фото 3504 с объяснением «пять портов данных — синий SFP и четыре жёлтых, порты можно агрегировать»; состав стандартного списка интерфейсов (management, redundancy-management, redundancy-port, service-port, virtual 1.1.1.1); поля страницы Edit целиком (MAC-адрес интерфейса, Guest LAN, Quarantine, NAS-ID, Backup Port, Dynamic AP Management, IPv6, DHCP Proxy Mode, ACL, mDNS); предупреждение при Apply; и последний шаг — переназначение интерфейса существующей WLAN `User_Data_WIFI` с `management` на новый, чего в тексте 13.3.7 нет.

## Предложение по пересборке

**Формат:** видео с генерированным голосом (код-рендер) ~3:00 на макетах GUI WLC (Controller › Interfaces: список, New, Edit; WLANs › Edit › General). Второй эпизод серии «WLC: WPA2 Enterprise»; сценарий — упражнение симулятора WLC.

Сцены для генератора:

1. **Порты vs интерфейсы** → рендер 3504 с пятью портами; из порта 1 «вырастают» два виртуальных интерфейса `management (VLAN 1)` и `vlan5_userdata (VLAN 5)` → «Порт физический, интерфейсы — виртуальные; каждой WLAN — свой.»
2. **Адресация** → топология: WLC 192.168.5.254, R1 F0/1.5 192.168.5.1, DHCP-пул на R1 → «Контроллер — .254, шлюз и DHCP — маршрутизатор .1.»
3. **Controller › Interfaces** → таблица из пяти стандартных строк → New → Interface Name `vlan5_userdata`, VLAN Id `5` → Apply → «Создаём интерфейс.»
4. **Edit** → Port Number `1`; VLAN 5; IP `192.168.5.254`; Netmask `255.255.255.0`; Gateway `192.168.5.1`; Primary DHCP Server `192.168.5.1` → Apply → OK на предупреждении → «Порт, адрес, шлюз, DHCP-сервер.»
5. **Проверка** → таблица: шестая строка `vlan5_userdata · 5 · 192.168.5.254 · Dynamic` → «Интерфейс в списке.»
6. **Привязка** → WLANs › User_Data_WIFI › General › Interface: `management` → `vlan5_userdata` → Apply; на топологии ноутбук «переезжает» из VLAN 1 в VLAN 5 → «Теперь клиенты этой WLAN — в VLAN 5.»

Ассеты: рендер 3504 (порты); макеты Controller › Interfaces (список / New / Edit со всеми секциями), WLANs › Edit › General; топология с подписями адресов.
