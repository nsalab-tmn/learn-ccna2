## Цель для обучающегося

Обучающийся должен уметь объяснить: (1) как два поддельных gratuitous ARP переписывают ARP-кэши PC1 и R1 и превращают PC2 в «человека посередине» (man-in-the-middle); (2) как хост, рассылающий BPDU с приоритетом 0, становится корневым мостом и меняет логическую топологию так, что весь трафик домена идёт через него; (3) какую информацию (IOS version, platform, IP, port ID) CDP раздаёт в открытом виде каждые 60 с и какими командами это выключить (`no cdp run`, `no cdp enable`, `no lldp run`, `no lldp transmit` / `no lldp receive`).

Текст темы (10.5.7–10.5.10) покрывает все три атаки, включая те же три шага ARP-отравления с иллюстрациями и ту же картинку Wireshark. Видео добавляет: анимацию обмена (два gratuitous ARP с текстом «10.0.0.1 is CC:CC:CC» / «10.0.0.11 is CC:CC:CC» и подсветкой изменившихся строк кэшей), анимацию «BPDU с приоритетом 0 → перестройка дерева: блокируется канал между настоящими коммутаторами», расшифровку полей CDP прямо на скриншоте (Software Version — C3550 IOS 12.2(40)SE, Platform WS-C3550-24-PWR, Addresses, Port ID FastEthernet0/21) и команды для LLDP, которых в видео 10.5.1 не было.

## Предложение по пересборке

**Формат:** `текст + иллюстрация` для CDP (текст 10.5.10 уже содержит ту же картинку Wireshark и все команды) **плюс** две анимации Figma (≤ 60 с каждая): (а) «ARP-отравление: два gratuitous ARP и перенаправление потока», (б) «STP: хост с приоритетом 0 становится корнем». Озвучка не нужна — текст темы в этом месте подробнее видео.

Сцены для генератора:

*Анимация A — ARP poisoning (≤ 60 с):*
1. Коммутатор, PC1 (10.0.0.11 / BB:BB:BB), R1 (10.0.0.1 / AA:AA:AA), PC2-злоумышленник (10.0.0.12 / CC:CC:CC); три ARP-кэша с верными записями → «Все кэши верны».
2. От PC2 два конверта: «10.0.0.1 is CC:CC:CC» к PC1, «10.0.0.11 is CC:CC:CC» к R1 → «Два незапрошенных ARP-ответа».
3. В кэше PC1 строка `10.0.0.1` меняет MAC на `CC:CC:CC` (подсветка), в кэше R1 строка `10.0.0.11` → `CC:CC:CC` → «Кэши отравлены».
4. Конверт данных PC1 → SW → PC2 → SW → R1, ответ тем же путём; у PC2 значок «глаз» → «PC2 видит и может менять весь трафик PC1 ↔ R1».
5. Ярлык `DAI` (Dynamic ARP Inspection) на коммутаторе, поддельный ARP отброшен → «Защита: DAI (тема 11)».

*Анимация B — STP root attack (≤ 60 с):*
1. Два коммутатора (левый «Root, priority 8192»), между ними ✓; снизу хост злоумышленника к обоим, на его каналах ✗/✓ → «Нормальная топология».
2. От хоста к обоим коммутаторам летят BPDU «Priority = 0» → «Хост рассылает BPDU с приоритетом 0».
3. Подпись «Root Bridge» перемещается на хост; ✗ появляется на канале между коммутаторами, оба канала к хосту ✓ → «Коммутаторы выбирают его корнем и блокируют свой прямой канал».
4. Поток трафика между коммутаторами идёт через хост → «Весь трафик домена проходит через злоумышленника».
5. Ярлык `spanning-tree bpduguard enable` на портах доступа, порт хоста уходит в err-disabled → «Защита: BPDU Guard (модуль 5/11)».

Ассеты: коммутатор, два ПК, маршрутизатор, фигура злоумышленника; блоки «ARP Cache» (IP | MAC) с подсвечиваемыми строками; конверты ARP/BPDU с текстом; значки ✓ / ✗ (Forward / Block); ярлыки команд.

Команды из видео (для справочного блока в тексте и для упражнения симулятора «выключить CDP/LLDP на портах доступа»):

```
Switch(config)# no cdp run
Switch(config-if)# no cdp enable
Switch(config)# no lldp run
Switch(config-if)# no lldp transmit
Switch(config-if)# no lldp receive
```
