## Описание сценария

Адреса IPv6 компьютеры могут получать автоматически тремя способами. При SLAAC (автоматической настройке адреса без сохранения состояния) компьютер строит адрес сам из префикса, который сообщает маршрутизатор в объявлении маршрутизатора (RA), а адрес DNS-сервера и имя домена не получает. При DHCPv6 без сохранения состояния адрес строится так же, а остальные параметры компьютер запрашивает у сервера DHCPv6; при DHCPv6 с сохранением состояния сервер выдает в аренду и сам адрес. Какой способ использовать, компьютерам сообщают флаги O и M в объявлении маршрутизатора.

Согласно сценарию, компания выросла, и сетевые администраторы больше не могут назначать адреса IPv6 устройствам вручную. Два маршрутизатора, R1 и R2, соединены между собой, и к каждому подключена локальная сеть с коммутатором и компьютером: PC-A в сети R1, PC-B в сети R2. Вам, сетевому администратору компании, нужно задать маршрутизаторам основные параметры и адреса, проверить, что PC-A получает адрес по SLAAC, настроить R1 сервером DHCPv6 без сохранения состояния для сети PC-A и сервером DHCPv6 с сохранением состояния для сети PC-B, а R2 — агентом ретрансляции DHCP, который передает запросы PC-B серверу на R1.

## Задачи лабораторной работы

- Настроить основные параметры, адреса IPv6 и маршруты по умолчанию на маршрутизаторах R1 и R2
- Проверить получение компьютером PC-A адреса по SLAAC
- Настроить на R1 сервер DHCPv6 без сохранения состояния для сети PC-A
- Настроить на R1 сервер DHCPv6 с сохранением состояния для сети PC-B
- Настроить на R2 агент ретрансляции DHCP и проверить адрес компьютера PC-B
- Проверить связь между локальными сетями

## Описание топологии

Топология состоит из двух маршрутизаторов R1 и R2, двух коммутаторов S1 и S2 и двух компьютеров PC-A и PC-B: маршрутизаторы соединены между собой, PC-A подключен к R1 через коммутатор S1, а PC-B — к R2 через коммутатор S2.
