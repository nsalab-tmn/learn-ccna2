## Описание сценария

Магистральный канал (trunk) передает кадры нескольких сетей VLAN по одному соединению между коммутаторами: каждый кадр получает тег 802.1Q с номером своей сети VLAN, и только кадры собственной VLAN (native VLAN) передаются без тега. Порт становится магистральным по настройке администратора или по договоренности с соседним коммутатором, которую выполняет протокол динамического согласования магистральных каналов (DTP). Согласование упрощает настройку, но статический магистральный канал с отключенным DTP предсказуемее: его режим не зависит от настройки соседнего порта.

Согласно сценарию, в офисе работают три коммутатора: коммутатор S1 соединяет коммутаторы S2 и S3, к которым подключены компьютеры сотрудников. Компьютеры трех отделов нужно разделить по сетям VLAN 10 Red, 20 Blue и 30 Yellow так, чтобы компьютеры одного отдела связывались друг с другом через все три коммутатора. На коммутаторах уже созданы сеть VLAN 99 Management для управления и сеть VLAN 999 Native для собственной VLAN. Вам, сетевому администратору, предстоит создать сети VLAN отделов и назначить им порты, настроить магистральный канал между S1 и S2 с согласованием по протоколу DTP, а между S1 и S3 — статический магистральный канал без DTP, перевести магистральные каналы на собственную VLAN 999 и выяснить, почему один из каналов не заработал.

## Задачи лабораторной работы

- Создать сети VLAN 10, 20 и 30 на коммутаторах S1, S2 и S3
- Назначить порты доступа коммутаторов S2 и S3 сетям VLAN
- Настроить магистральные каналы: с согласованием по протоколу DTP между S1 и S2 и статический между S1 и S3
- Назначить магистральным каналам собственную VLAN 999
- Перенастроить магистральный канал на коммутаторе S3
- Проверить связь между компьютерами одной сети VLAN

## Описание топологии

Топология состоит из трех коммутаторов S1, S2, S3 и шести компьютеров PC1–PC6: коммутатор S1 соединен с коммутаторами S2 и S3, и к каждому из коммутаторов S2 и S3 подключено по три компьютера.
