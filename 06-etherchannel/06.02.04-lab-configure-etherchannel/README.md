## Описание сценария

EtherChannel объединяет несколько физических каналов Ethernet между двумя коммутаторами в один логический — агрегированный канал. Коммутатор распределяет трафик по всем входящим в него каналам, поэтому их пропускная способность складывается, а при обрыве одного кабеля трафик продолжает идти по остальным. Без агрегации связующее дерево (протокол STP) из нескольких параллельных каналов оставляет работать только один, а остальные блокирует, чтобы не возникла петля. Договориться об агрегированном канале коммутаторы могут по протоколу PAgP или по протоколу LACP, описанному стандартом IEEE 802.3ad.

Согласно сценарию, в сети только что установлены три коммутатора, S1, S2 и S3, и каждая пара коммутаторов соединена двумя кабелями. Пока из двух параллельных каналов может работать только один, и половина пропускной способности соединений не используется. Вам, сетевому администратору, нужно задать коммутаторам имена, настроить соединяющие их порты как статические магистральные каналы (trunk) и объединить каждую пару кабелей в агрегированный канал: между S1 и S3 — по протоколу PAgP, между S1 и S2 и между S2 и S3 — по протоколу LACP, а затем убедиться, что протокол STP работает с агрегированными каналами как с отдельными портами.

## Задачи лабораторной работы

- Задать имена коммутаторов и настроить порты между ними как магистральные каналы
- Настроить агрегированный канал PAgP между коммутаторами S1 и S3
- Настроить агрегированный канал LACP между коммутаторами S1 и S2
- Настроить резервный агрегированный канал LACP между коммутаторами S2 и S3
- Проверить агрегированные каналы и связующее дерево
